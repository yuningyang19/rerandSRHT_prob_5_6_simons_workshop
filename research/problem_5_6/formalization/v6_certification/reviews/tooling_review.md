# Independent certification tooling review

Reviewer `/root/baseline_audit`, separate from tooling and additive proof authors. This is a bounded code and data audit of the actual files listed with SHA256 in `independent_tooling_snapshot.json`; it is not compiler authentication, mathematical originality review, final clean reproduction, or a publication approval.

## Checked behavior

`AuditTools.lean` reads constants from the checked environment, requires theorem declaration kind for targets, rejects unsafe constants, traverses both fully elaborated type constants and value/proof constants without a namespace filter, and descends into inductive constructors. Each target's `collectAxioms` set is checked against `{propext, Classical.choice, Quot.sound}`. A second traversal emits the actual graph, and Python independently recomputes reachable axiom sets and compares them with that metadata. Primitive expected definitions are recorded with raw type and body expressions and compared as a separate lock. The traversal reads checked constants; it does not insert a theorem or use an assumed conclusion.

The 189-target/62,407-node graph was independently parsed: one matching terminator, no duplicate target/node name, no missing referenced node, and no disallowed axiom node. The reviewed source has no actual `sorry`, `admit`, custom theorem axiom, native-computation proof axiom, unsafe proof escape, unchecked insertion or skipped kernel typechecking. Imported library trust is still subject to the required fresh kernel replay and source-cold build. A generated actual-type JSON alone is only a self-consistency comparator: reader-owned expected modules and independently reviewed definition meanings remain required.

`verify_evidence.py` rejects missing/extra/duplicate target inventories, wrong declaration kinds, mismatched expected type/body records, incomplete graph output, missing dependencies, forbidden axioms even outside the project namespace, stale source manifests, stale execution inputs/logs and absent mandatory checks. The exact local import closure and pinned build files are required, not any nonempty subset. Import scanning is adequate for the current checked single-module `import` lines; it is not claimed as a general Lean parser.

`run_logged.py` records real subprocess return code, command, cwd, timestamps, output hash and pre-execution local source/checker closure. Receipt source paths are independently recomputed for each required command, and exact command/cwd are verified. It transparently calls its output a local execution record rather than authenticated attestation. This closes stale-source acceptance in ordinary local execution; it cannot authenticate a maliciously fabricated receipt.

`run_suite.py` runs the unified target, independent expected assignments, actual semantic witness modules, structural guards, negative fixtures and kernel replay serially with failure propagation, then runs the CombinedAudit checker against reviewed locks. It does not request compiled caches. The suite's source is reviewed, but no successful suite/cold-build/export execution is inferred from reading it.

The independent reviewer reran all 15 isolated invalid Python fixtures; every fixture was rejected. They are data fixtures and introduce no false axiom into the Lean workspace. The command, exit code, results and tooling hashes are retained in `independent_tooling_snapshot.json`.

## Findings preserved and repairs checked

1. Initial mandatory-check verification accepted six keys pointing to the same unrelated successful command. Fixed by exact required command and cwd checks; the command-substitution negative fixture rejects it.
2. Initial source manifest checking accepted an arbitrary nonempty valid subset. Fixed by equality with the complete local import closure plus pinned build files; the omitted-member fixture rejects it.
3. Initial execution receipts could omit local source bindings while retaining old successful logs. Fixed by exact per-command closure equality, including checker scripts and imported local Python helpers; the deleted-source-binding fixture rejects it.
4. Three leading-space theorem declarations were transitively checked but absent from explicit inventory. The generator now strips whitespace; all three occur explicitly in the refreshed 189-target graph. The three same-line `@[simp] theorem adjoinedEarPoint_zero/last/internal` declarations were another concrete explicit-inventory omission, though transitively closed. The subsequent attribute-prefix stripping fix was read and correctly handles these lines; final graph refresh is still required.
5. The current combined execution receipt was observed to fail correctly with `stale execution source: .../scripts/verify_evidence.py`, because that checker changed after the receipt. The controller must rerun the real command after tooling freezes; editing the receipt hash is not an execution substitute.
6. `export_companion.py` uses deterministic Git-HEAD content, checks committed/clean selected files and exact B hashes, normalizes tar metadata and gzip timestamps, and emits an archive file manifest. Its initial prefix-based tracked-file selection does not itself reject accidentally tracked `.olean`, `.pyc`, `.lake`, `__pycache__` or native compiled objects. The subsequent explicit rejection of .lake/__pycache__ components and compiled-object suffixes was read and addresses the concrete finding. Final unpack/build verification remains mandatory.

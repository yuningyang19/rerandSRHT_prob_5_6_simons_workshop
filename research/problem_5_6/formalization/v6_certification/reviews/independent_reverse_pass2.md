## Material finding: the identity-norm sentence has an unspecified dimension boundary

C `main.tex:849–872` defines coordinate ranges `{1,...,N_u}` and real spaces `R^{N_u}` without explicitly imposing `N_u >= 1`. C `main.tex:958–969` says an inserted identity has norm one and that the modifications preserve the product of edge norms. The first claim is false for `R^0`: its only linear operator is zero and `||I_0||=0`. For an isolated zero-dimensional vertex a split changes the empty product of edge norms from one to zero. The generic splitting paragraph does not impose connectedness. Even for connected graphs, where an incident zero-dimensional edge forces both overall products to zero, the standalone identity-norm-one sentence remains false at dimension zero.

The formal code correctly distinguishes the cases. `PaperV6/GraphModifications.lean:101–111` (`paper_identity_norm`) requires `0<n`; `graph_fiber_norm_product:113–136` requires positive dimensions. `RootedHistoryExpected.lean:26–43` and `RootedHistory.lean:30–71` prove entry equality and norm-product nonincrease in all dimensions, and exact norm-product equality when dimensions are positive. The positivity premise is not explicitly present in the frozen C graph definition. The published Mingo–Speicher Definition 8 also describes finite-dimensional `C^{N_v}` without an explicit positive-size guard in the text inspected, so it does not independently resolve the ambiguity.

**Disposition:** `I-V6-11` cannot receive unconditional native literal-scope acceptance against unchanged C. This is a necessary scope clarification, not a counterexample to the rank-r graph bound or the OSE theorem. Minimal source correction: state positive integer coordinate dimensions in `def:graph-contraction`; alternatively say identity norms are at most one, preserve the finite sum, and the norm product does not increase, adding exact equality for positive dimensions. Any actual source change requires a new C binding; this audit changes no manuscript bytes.
